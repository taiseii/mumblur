# Mumbler — Swift Rewrite (Menu-Bar Push-to-Talk Dictation)

**Status:** Design proposed, pending approval
**Date:** 2026-05-27
**Target machine:** Apple Silicon (M3 Max, macOS Tahoe 26.x), single user
**Supersedes:** `2026-05-27-push-to-talk-dictation-design.md` (Python version) — same goals, new stack

## 1. Why a rewrite

The Python prototype works end-to-end (24 passing tests, slow integration test transcribes the fixture in ~25 s on first run). It fails at the last mile on macOS Tahoe 26.x because the OS will not honor Accessibility grants for ad-hoc-signed binaries running under terminals — neither the Homebrew Python interpreter, nor the Homebrew-cask Alacritty, nor pyenv-installed Python could be made trusted. The toggle in System Settings shows on, but `AXIsProcessTrusted()` returns `False`.

This is a stack mismatch, not a coding bug. macOS' permission model is built around `.app` bundles with stable identities, and a Python script through `uv` through a terminal is exactly the chain Tahoe locked down. Repackaging the Python as a signed `.app` would work but adds non-trivial build/signing infrastructure for a problem Swift solves natively.

The rewrite is therefore a port, not a redesign: the architecture (5 small modules with narrow contracts, locked state machine, worker thread, record-then-transcribe semantics) carries over verbatim. Only the implementation language and platform APIs change.

## 2. Goal

A local push-to-talk dictation tool for macOS Apple Silicon, distributed as `Mumbler.app`. The user holds **Right Option** while speaking; on release, the recorded audio is transcribed locally and pasted at the cursor in the active app. Everything runs on-device. No network.

## 3. Scope

### In scope (v1)

- A single `Mumbler.app` bundle (ad-hoc signed for personal use; no Apple Developer account needed).
- Menu-bar-only UI: an `NSStatusItem` with three visible states — idle (mic icon), recording (red dot), transcribing (small spinner). One menu item to quit.
- Global push-to-talk hotkey, default **Right Option**, via `CGEventTap` on `flagsChanged` events.
- 16 kHz mono mic capture via `AVAudioEngine` for the duration of the hold.
- Record-then-transcribe: on release, the buffer is handed to WhisperKit, then the result is pasted at the cursor via `NSPasteboard` + synthesized ⌘V.
- WhisperKit with `whisper-large-v3-turbo` Core ML model, auto-downloaded on first launch.
- Multilingual auto-detect.
- macOS Accessibility and Microphone permission prompts handled natively via the OS dialog.
- Locked state machine with worker thread for transcription — same single-flight semantics as the Python version (`IDLE → RECORDING → TRANSCRIBING → IDLE`, new presses during `TRANSCRIBING` are rejected).

### Out of scope (v1)

- LoRA fine-tuning (deferred phase 2).
- Streaming transcription / partial results during hold.
- Voice Activity Detection.
- Configurable hotkey (default `alt_r` only in v1; user-configurable in v2).
- Preferences window or any non-menu-bar UI.
- launchd / auto-start at login.
- Auto-update / Sparkle / TestFlight.
- Code signing with a Developer ID certificate (ad-hoc is sufficient for single-user use; Developer ID added only if/when distributing to others).
- Notarization.
- Pasteboard restoration after paste.
- Telemetry, crash reporting, multi-user support.

### Non-goals (explicit)

- Cross-platform support. macOS Apple Silicon only, Tahoe 26.x target.
- Sub-100 ms latency. Same target as Python version: "feels instant for short utterances."
- Reuse of any Python code at runtime. The Python implementation stays on disk as a reference but is not invoked.

## 4. What carries over from the Python design

- **Architecture pattern**: five narrow components — Audio, Paste, Transcribe, Hotkey, Runner — wired by an app entry point.
- **State machine**: `IDLE / RECORDING / TRANSCRIBING`, locked, worker thread for inference, single-flight rejection of presses during `TRANSCRIBING`, min-hold guard.
- **Test fixture**: `tests/fixtures/hello_world.wav` (already generated by macOS `say`) is reused for the WhisperKit integration test.
- **Verification harness pattern**: per-task gate (`scripts/verify_task.sh N`) that ensures executions of the implementation plan work together. Adapted for Swift toolchain (`xcodebuild test` + `swift test` instead of pytest).
- **Specs/plans directory**: `docs/superpowers/{specs,plans}/` continues to host design and implementation docs.
- **Branching**: continue on `feat/mvp` for spec/plan commits; the Swift implementation lives on a new branch `feat/swift` cut from `master` so the Python prototype's code stays accessible on `feat/mvp` for reference.

## 5. Architecture

### 5.1 Process model

A single foreground macOS app (`Mumbler.app`) with `LSUIElement = true` in `Info.plist` — meaning no Dock icon, only the menu bar. WhisperKit is initialized on app launch and kept resident. The hotkey listener runs on the main run loop via `CGEventTap`. Mic capture runs in `AVAudioEngine`'s internal thread. Transcription + paste runs on a dedicated `DispatchQueue` (the "worker"), keeping the main thread free for menu bar / event tap responsiveness.

### 5.3 Module contracts

Same shape as Python; Swift signatures below.

**`AudioRecorder`**
```swift
final class AudioRecorder {
    init() throws  // configures AVAudioEngine; doesn't start
    func start() throws            // installs tap, starts engine
    func stop() -> [Float]         // returns accumulated samples, resets buffer
    func abortIfActive()           // best-effort cleanup; never throws
}
```
- Always 16 kHz mono float32. If the input device's native rate differs, install an `AVAudioConverter` to downsample inside the tap callback.
- Internally uses `inputNode.installTap(onBus:bufferSize:format:block:)`.

**`Paster`**
```swift
struct Paster {
    func paste(_ text: String)     // no-op on empty/whitespace
}
```
- Writes `text` to `NSPasteboard.general` (clear + setString).
- Synthesizes ⌘V via `CGEvent(keyboardEventSource:virtualKey:keyDown:)` with `.maskCommand` flags. No subprocess shelling out to `pbcopy`.

**`Transcriber`**
```swift
actor Transcriber {
    init(modelName: String, language: String) async throws
    func transcribe(_ samples: [Float]) async throws -> String
}
```
- `actor` for thread-safe access to the WhisperKit instance.
- `transcribe` returns the joined, trimmed string. Empty input → empty string without invoking the model.
- WhisperKit is created with `WhisperKit(modelName: ..., modelFolder: nil)` so it auto-downloads on first call.

**`Hotkey`**
```swift
enum HotkeyEvent { case press, release }

final class Hotkey {
    init(targetFlag: CGEventFlags, onEvent: @escaping (HotkeyEvent) -> Void)
    func start() throws            // installs CGEventTap; requires Accessibility
    func stop()
}
```
- Watches `.flagsChanged` events on `kCGSessionEventTap`. Right Option corresponds to keycode `kVK_RightOption` (0x3D) with the `.maskAlternate` flag set.
- Detects transitions: previously-down → now-up = release; previously-up → now-down = press. Auto-repeat is irrelevant for flagsChanged.
- Other keys with same flag (e.g., Left Option) are distinguished by the event's `getIntegerValueField(.keyboardEventKeycode)`.

**`Runner`**
```swift
final class Runner {
    enum State: String { case idle, recording, transcribing }

    init(recorder: AudioRecorder, transcriber: Transcriber, paster: Paster,
         minHoldMs: Int, worker: DispatchQueue)
    var state: State { get }       // thread-safe via lock
    func onPress()                 // listener thread
    func onRelease()               // listener thread
    func shutdown()                // abort recording if active
}
```
- Internal `os_unfair_lock` (or `NSLock`) guards state transitions, mirroring the Python `threading.Lock` design.
- `onRelease` dispatches the transcribe-and-paste pipeline to `worker`. The dispatch is what makes "press during transcription" a real, observable behavior.

**`PermissionGate`**
```swift
enum PermissionResult { case granted, denied, prompted }

enum PermissionGate {
    static func ensureAccessibility(prompt: Bool) -> PermissionResult
    static func ensureMicrophone() async -> PermissionResult
}
```
- Accessibility check uses `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt.takeUnretainedValue(): true])` to trigger the system dialog the first time.
- Microphone check uses `AVCaptureDevice.requestAccess(for: .audio)` which also pops the system dialog.
- Both prompt the user *correctly* because the requesting process is `Mumbler.app` — a real signed bundle with usage description strings in `Info.plist`.

**`MenuBar`**
```swift
final class MenuBar {
    init(quit: @escaping () -> Void)
    func setState(_ state: Runner.State)   // updates icon
}
```
- `NSStatusItem` with three template images: `mic` (idle), `mic.fill` (recording, tinted red via `NSImage.recolor`), `mic.badge.plus` or a small `NSProgressIndicator` overlay for transcribing.
- A single menu item: "Quit Mumbler".

### 5.4 Data flow

```
[Mumbler.app launch]
   PermissionGate.ensureAccessibility(prompt: true) → granted?
   PermissionGate.ensureMicrophone() → granted?
   transcriber = Transcriber(modelName: "large-v3-turbo", language: "auto")
   recorder    = AudioRecorder()
   hotkey      = Hotkey(targetFlag: .maskAlternate, onEvent: runner.handle(_:))
   runner      = Runner(recorder, transcriber, paster, minHoldMs: 200, worker: bgQueue)
   menuBar.setState(.idle)
   hotkey.start()

[Right Option pressed — listener thread]
   runner.onPress() → lock → state was IDLE → state = RECORDING → unlock
                   → recorder.start()
                   → menuBar.setState(.recording)   // hopped to main thread

[Right Option released — listener thread]
   runner.onRelease() → lock → state was RECORDING → unlock
                     → samples = recorder.stop()
                     → if held < minHoldMs: state = IDLE, return
                     → lock → state = TRANSCRIBING → unlock
                     → menuBar.setState(.transcribing)
                     → worker.async { runner.doWork(samples) }

[Worker queue]
   doWork(samples):
     do {
       let text = try await transcriber.transcribe(samples)
       if !text.isWhitespaceOnly { paster.paste(text) }
     } catch {
       NSLog("transcription failed: %@", error.localizedDescription)
     }
     lock → state = IDLE → unlock
     menuBar.setState(.idle)
```

### 5.5 Permission flow

The crucial difference from the Python version. Because `Mumbler.app` is a signed bundle:

1. On first launch, `PermissionGate.ensureMicrophone()` triggers `AVCaptureDevice.requestAccess(.audio)`. macOS reads `NSMicrophoneUsageDescription` from `Info.plist` and presents the official dialog. User clicks Allow.
2. `PermissionGate.ensureAccessibility(prompt: true)` calls `AXIsProcessTrustedWithOptions` with the prompt option. macOS shows a dialog with "Open System Settings" → directs user to Privacy & Security → Accessibility. User toggles Mumbler **ON** (the entry is created automatically because the prompt was triggered).
3. After both grants, `hotkey.start()` succeeds.
4. If either grant is denied, the menu bar icon shows a warning state and clicking it opens System Settings to the relevant pane.

This is fundamentally different from the Python version because the requesting identity is a stable `.app` bundle that TCC tracks by `CFBundleIdentifier` + cdhash. Toggle stays on, doesn't drift across updates, doesn't depend on which terminal launched anything.

## 6. WhisperKit integration

- Package: `https://github.com/argmaxinc/argmax-oss-swift` (SwiftPM dependency).
- Import: `import WhisperKit`.
- Model: pass `modelName: "large-v3-turbo"` (or `"openai_whisper-large-v3-v20240930_turbo"` — exact name to be confirmed during implementation against argmax's HuggingFace model list).
- Storage: WhisperKit caches into `~/Library/Application Support/com.mumbler.mumbler/whisperkit/` (or its default cache path).
- Inference call: `try await whisperKit.transcribe(audioArray: samples)?.text ?? ""`.
- WhisperKit accepts `[Float]` directly — no temp WAV needed.
- Multilingual: pass `decodingOptions: DecodingOptions(language: nil)` for auto-detect (`nil` ≈ auto in WhisperKit's API; exact field name to be confirmed in plan stage).

## 7. CLI vs menu bar UX

The Python version was a foreground CLI. The Swift version is a menu bar app — launch by double-clicking `Mumbler.app` in Finder, by Spotlight, or by `open Mumbler.app` from a terminal.

The menu bar provides:
- Visual state feedback (idle/recording/transcribing icons).
- Quit command.
- If permissions are missing: a "Grant permissions…" menu item that opens System Settings to the right pane.

No preferences window in v1.

## 8. Testing strategy

XCTest target inside the Xcode project. Tests are pure-logic unit tests for the modules whose contracts don't require macOS UI:

- **`AudioRecorderTests`** — inject a fake `AVAudioFormat` and verify the resampling + buffer accumulation logic with synthesized samples.
- **`PasterTests`** — `paste("hello")` then read back from `NSPasteboard.general`. Skip the ⌘V keystroke assertion (no active app in tests). Document this gap.
- **`TranscriberTests`** — unit tests with a fake `WhisperKitProtocol`. A `@MainActor`-marked integration test loads the real model and transcribes `hello_world.wav` (the same fixture from the Python version); marked `slow` and excluded from the default test scheme.
- **`HotkeyTests`** — test the `Dispatcher` logic that translates `flagsChanged` deltas into press/release events. The actual `CGEventTap` is exercised only manually.
- **`RunnerTests`** — inject all dependencies as fakes; verify state transitions, single-flight rejection (use a deferred worker mirroring the Python design), min-hold discard, exception handling, shutdown.

Slow integration test runs via `xcodebuild test -only-testing:MumblerTests/TranscriberTests/testIntegrationTranscribesHelloWorldFixture`.

## 9. Build & signing

- `xcodebuild -project Mumbler.xcodeproj -scheme Mumbler -configuration Release` produces `build/Release/Mumbler.app`.
- Ad-hoc sign with `codesign --force --sign - --options runtime Mumbler.app`. Tahoe will honor the ad-hoc signature for a `.app` bundle (unlike for bare CLI binaries).
- Install: copy to `/Applications/Mumbler.app`.
- `scripts/build_app.sh` wraps build + sign + (optionally) copy-to-/Applications for one-command iteration.

## 10. Verification harness

`scripts/verify_task.sh` adapted for the Swift toolchain:

- File-existence checks (xcodeproj, source files, Info.plist, etc.) — same pattern as Python.
- `xcodebuild -list -project Mumbler.xcodeproj` to confirm scheme presence.
- `xcodebuild build -scheme Mumbler -destination 'platform=macOS' -configuration Debug -quiet` to confirm the project compiles after each task.
- `xcodebuild test -scheme Mumbler -only-testing:MumblerTests -destination 'platform=macOS' -quiet` for the fast tests.
- Final smoke gate: `codesign -dv build/Debug/Mumbler.app | grep Identifier` confirms the bundle has a stable identity.

Like the Python version, each task ends with `scripts/verify_task.sh N` as the gate. A fresh subagent picking up Task N can run `scripts/verify_task.sh N-1` to confirm the prior state.

## 11. Open questions (documented, not blocking the MVP)

1. **Exact WhisperKit model name.** "large-v3-turbo" is the canonical name but argmax sometimes uses date-suffixed variants (e.g., `large-v3-v20240930_turbo`). Resolved by listing models on first launch and picking the largest turbo variant — handled in the plan, not the spec.
2. **Right Option keycode distinction.** Whether to distinguish Right Option from Left Option using `keyboardEventKeycode` (== `kVK_RightOption` 0x3D) or by checking the modifier flag bit. Both should work; pick one in the plan.
3. **Menu bar icon for transcribing.** Animated spinner vs static icon vs SF Symbol with `.replace` animation. UX detail; defer to plan.
4. **Bundle identifier.** `world.questable.mumbler` (matches the user's domain) or `com.mumbler.mumbler` (more generic). Pick in the plan.

## 12. Definition of Done

- `Mumbler.app` builds via `scripts/build_app.sh` and installs to `/Applications/`.
- First launch prompts for Microphone and Accessibility via the OS-native dialogs; both grants stick across reboot.
- Holding Right Option for ≥ 200 ms while speaking, then releasing, pastes the transcript at the cursor in any focused app within roughly decode time (≤ 1 s for short utterances).
- Menu bar icon visibly transitions between idle / recording / transcribing.
- Pressing Right Option while a previous transcription is still running prints to log and is rejected (single-flight); the in-flight transcription completes and pastes.
- `xcodebuild test` (fast suite) passes; the slow integration test passes on the dev machine.
- The Python implementation on `feat/mvp` is left intact as a reference; the Swift implementation lives on `feat/swift`.
